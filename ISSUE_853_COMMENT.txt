## Evaluation Complete: Deferring to Backlog

After thorough evaluation, we're **deferring** GLM-OCR integration due to a critical architectural blocker.

### Decision Summary

**Status**: DEFER
**Reason**: Architectural mismatch - requires sidecar HTTP server process
**Documentation**: See `docs/architecture/deferred-features.md`

### Critical Blocker: Architectural Mismatch

GLM-OCR requires a **persistent HTTP sidecar daemon** (vLLM/SGLang/MLX server) for all self-hosted backends. Our current provider abstraction is designed for **in-process** model execution:

- ✅ Current: `llama-cpp-python`, `mlx-lm` run in-process
- ❌ GLM-OCR: Requires external HTTP server process with lifecycle management

Implementing this would require:
- New provider abstraction supporting server-process models
- Sidecar daemon lifecycle management (start/stop/health checks)
- Inter-process communication layer
- Port management and conflict resolution

**Estimated effort**: 3-5 development sessions

### Hard Constraint: Dependency Conflict

GLM-OCR cannot coexist with vLLM in the same environment:

```
vLLM:      transformers<5
GLM-OCR:   transformers>=5.3.0
Result:    INCOMPATIBLE
```

### Non-Blocking Concerns (Resolved)

The following were evaluated and found acceptable:

✅ **Transformers version**: Lock file already pins `transformers==5.3.0`
✅ **VRAM**: 2.65 GB (BF16) is manageable; 13 quantizations available
✅ **License**: Apache 2.0 + MIT are compatible

### Revisit Conditions

We'll reconsider this feature if/when:

1. **Server-process provider type added**: Project implements Ollama-style deployment with sidecar lifecycle management
2. **Dependency conflict resolved**: Alternative backend supports `transformers>=5.3.0`
3. **In-process GLM-OCR**: Community develops in-process inference (unlikely)

### Alternative Solutions

For scanned/image-based PDF OCR:

- **Tesseract OCR**: Established open-source engine
- **EasyOCR**: Python-based with GPU support
- **PaddleOCR**: High-performance multilingual OCR
- **Cloud APIs**: Google Vision, Azure Vision (requires network)
